# Python Migration Plan — avoxi-ai-agent

**Audience:** an implementer (Codex) who has access to this repository.
**Goal:** replace the existing five-module TypeScript MVP with an equivalent Python implementation that preserves all module contracts and design principles. The user-facing command becomes `uv run audit` instead of `pnpm audit`. Behavior is identical.

This plan has been audited (Claude + Codex second opinions) and incorporates the resulting fixes. Implement it as written; do not redesign.

## 1. Design principles (preserved verbatim)

The project follows John Ousterhout's *A Philosophy of Software Design*. The Python version must preserve these:

- **Deep modules.** Every module hides substantial complexity behind a narrow interface.
- **Information hiding.** Avoxi wire field names (`avoxi_call_id`, `agent_actions`, etc.) stop at `avoxi.py`. Per-provider LLM base URLs stop at `config.py`. Downstream modules see domain-neutral names.
- **Define errors out of existence.** `list_calls` returns `[]` for empty windows. `classify` never raises. `Analysis` is a discriminated union — answered calls cannot carry a miss reason at the type level.
- **Pure where it can be.** `journey.py` has no I/O and does not call `datetime.now()` except inside `previous_shift`, where it accepts an explicit `now` argument.
- **Strategic > tactical.** Five modules. Don't add a sixth.

### 7.2 `src/avoxi_audit/config.py`

**Surface:** `load_config() -> AppConfig`

**Behavior:**

1. Call `dotenv.load_dotenv()` at import time (or lazily in `load_config`).
2. Resolve schedule path:
   - If `SCHEDULE_PATH` env var is set → use that path.
   - Else → `Path.cwd() / "config" / "schedule.yaml"`.
3. Validate env vars and YAML with pydantic v2.
4. Return a fully-resolved `AppConfig`.
5. Raise a clear `ValueError`/`RuntimeError` with field path on invalid config.

**Provider base URL table** (lives here, nowhere else):

```python
PROVIDER_BASE_URLS: dict[str, str] = {
    "kimi":   "https://api.moonshot.cn/v1",
    "gemini": "https://generativelanguage.googleapis.com/v1beta/openai/",
    # "openai" intentionally absent — use SDK default by passing base_url=None
}
```

**Resolution rule for `LlmConfig.base_url`** (decision from audit M2):

- If `LLM_BASE_URL` env var is set → use it.
- Else if provider is `openai` → leave `None` (let the SDK pick its default).
- Else → look up `PROVIDER_BASE_URLS[provider]`.

`LlmConfig.base_url` is typed `str | None`. `audit.py` passes whatever it gets to `OpenAI(base_url=...)`.

**Pydantic schemas:**

```python
from typing import Literal
from pydantic import BaseModel, Field

Weekday = Literal["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]
Provider = Literal["kimi", "openai", "gemini"]

class Window(BaseModel):
    name:  str | None = None
    days:  list[Weekday]
    start: str = Field(pattern=r"^\d{2}:\d{2}$")
    end:   str = Field(pattern=r"^\d{2}:\d{2}(\+1)?$")

class Schedule(BaseModel):
    timezone: str
    windows:  list[Window] = Field(min_length=1)

class AvoxiConfig(BaseModel):
    token:    str = Field(min_length=1)
    base_url: str = "https://genius.avoxi.com/api/v2"

class LlmConfig(BaseModel):
    provider: Provider
    api_key:  str = Field(min_length=1)
    model:    str = Field(min_length=1)
    base_url: str | None = None

class AppConfig(BaseModel):
    avoxi:        AvoxiConfig
    llm:          LlmConfig
    schedule:     Schedule
    company_name: str = "your company"
```

**Env var → field mapping:**

| Env var | Required | Field |
|---|---|---|
| `AVOXI_API_TOKEN` | yes | `avoxi.token` |
| `AVOXI_BASE_URL` | no | `avoxi.base_url` (default in schema) |
| `LLM_PROVIDER` | yes | `llm.provider` |
| `LLM_API_KEY` | yes | `llm.api_key` |
| `LLM_MODEL` | yes | `llm.model` |
| `LLM_BASE_URL` | no | `llm.base_url` (overrides provider default) |
| `COMPANY_NAME` | no | `company_name` (default `"your company"`) |
| `SCHEDULE_PATH` | no | (used to locate YAML, not stored in config) |

**Module docstring:** start with a doc comment that mirrors `src/config.ts`'s top-of-file comment. Document that `LlmConfig.base_url` may be `None`, meaning "use the SDK's default base URL".

### 7.3 `src/avoxi_audit/journey.py`

**Surface:** three pure functions + types.

```python
def is_on_call(at: datetime, schedule: Schedule) -> bool: ...
def classify(call: Call, schedule: Schedule) -> Analysis: ...
def previous_shift(now: datetime, schedule: Schedule) -> tuple[datetime, datetime]: ...
```

`previous_shift` returns `(since, until)`. All datetimes throughout this module are **timezone-aware** — naive datetimes are a programming error.

**Imports (type-only across modules):**

```python
from .avoxi import Call, Event
from .config import Schedule, Window, Weekday
```

**Types defined here:**

```python
from dataclasses import dataclass
from typing import Literal

StepKind = Literal[
    "hit_did", "forwarded", "ring_agent", "agent_declined",
    "agent_answered", "queued", "voicemail", "hangup", "other",
]

MissReason = Literal[
    "no_agent_on_duty", "agent_declined", "ring_timeout",
    "queue_abandoned", "voicemail_left", "voicemail_empty",
    "routing_failure", "off_hours_expected", "unknown",
]

@dataclass(frozen=True)
class Step:
    at:     datetime
    kind:   StepKind
    actor:  str | None = None
    detail: str | None = None

@dataclass(frozen=True)
class MissedAnalysis:
    steps:  list[Step]
    reason: MissReason
    missed: Literal[True] = True

@dataclass(frozen=True)
class AnsweredAnalysis:
    steps:  list[Step]
    missed: Literal[False] = False

Analysis = MissedAnalysis | AnsweredAnalysis
```

**`is_on_call` implementation notes:**

```python
from zoneinfo import ZoneInfo

def is_on_call(at: datetime, schedule: Schedule) -> bool:
    local = at.astimezone(ZoneInfo(schedule.timezone))
    weekday = local.strftime("%a")  # "Mon", "Tue", ...
    hhmm = local.strftime("%H:%M")
    return any(_in_window(weekday, hhmm, w) for w in schedule.windows)
```

`_in_window` mirrors the TS `inWindow`:
- Non-cross-midnight: `weekday in w.days and w.start <= hhmm < end_time` (string comparison works because zero-padded).
- Cross-midnight (`end` ends with `+1`): two parts — Part A (start day, `hhmm >= start`) OR Part B (next day, `hhmm < end`).
- `end == "24:00"` is the full-day case; non-cross-midnight handles it correctly because `hhmm < "24:00"` is always true for valid HH:MM.

`_next_weekday(day)` cycles through `["Sun", "Mon", "Tue", "Wed", "Thu", "Fri", "Sat"]`.

**`classify` priority ladder** (port verbatim from `src/journey.ts`):

```
1. routing_failure   if call.forwardedTo is empty AND no finalDestination
2. agent_declined    if any step kind is 'agent_declined'
3. voicemail_left    if last step kind is 'voicemail'   # M2 will distinguish empty vs left
4. queue_abandoned   if 'queued' present AND no 'agent_answered'
5. ring_timeout      if 'ring_agent' present AND no 'agent_answered'
6. is_on_call(call.started_at, schedule) → 'no_agent_on_duty' else 'off_hours_expected'
7. fallthrough → 'unknown'
```

`classify` never raises. For answered calls (`call.status == "answered"`), return `AnsweredAnalysis(steps=...)` directly without consulting the ladder.

**`previous_shift` implementation:**

Decision from audit H2: **search bound is 14 days** (was 9). If no shift is found, raise:

```python
raise RuntimeError(
    "Schedule has no completed on-call window in the last 14 days. "
    "Check config/schedule.yaml — at least one window must end within this period."
)
```

Algorithm:

1. `now` must be timezone-aware. If not, raise `ValueError`.
2. Convert `now` to schedule timezone for date iteration.
3. For `days_back in range(14)`:
   - Compute the local date `today_local - days_back`.
   - Find the weekday for that date.
   - For each window where this weekday is in `window.days`:
     - Compute window start as a tz-aware datetime: `datetime(year, month, day, start_h, start_m, tzinfo=ZoneInfo(schedule.timezone))`.
     - Compute window end similarly. If `crosses_midnight` or `end == "24:00"`, use the next local date.
     - If `end <= now`, this is a candidate. Keep the candidate with the latest `end`.
4. Return `(since, until)` of the latest candidate. Both are timezone-aware (UTC offset preserved).

Use `zoneinfo.ZoneInfo` and arithmetic on `datetime` directly. **Do not** replicate the TypeScript `sv-SE` offset trick — it was a workaround for JavaScript's missing tz support and Python doesn't need it.

### 7.4 `src/avoxi_audit/avoxi.py`

**Surface:**

```python
class AvoxiClient:
    def __init__(self, cfg: AvoxiConfig) -> None: ...
    def __enter__(self) -> "AvoxiClient": ...
    def __exit__(self, *exc) -> None: ...
    def list_calls(self, since: datetime, until: datetime) -> list[Call]: ...
```

**Domain types (exported from this module):**

```python
@dataclass(frozen=True)
class Event:
    at:    datetime
    kind:  str
    actor: str | None = None

@dataclass(frozen=True)
class Call:
    id:                 str
    status:             Literal["answered", "unanswered", "voicemail"]
    direction:          Literal["inbound", "outbound", "internal"]
    from_:              str   # `from` is reserved; use trailing underscore (idiomatic Python)
    to:                 str
```

> **Note:** `from_` is the standard Python idiom for shadowing the keyword. Document it in the dataclass docstring.

**Wire schemas (private, pydantic v2):**

```python
from pydantic import BaseModel, ConfigDict
from datetime import datetime

class _WireEvent(BaseModel):
    model_config = ConfigDict(extra="allow")  # equivalent to zod .passthrough()
    timestamp:  datetime
    event_type: str
    actor:      str | None = None

class _WireCall(BaseModel):
    model_config = ConfigDict(extra="allow")
    avoxi_call_id:     str
    status:            str = "unanswered"
    direction:         str = "inbound"
    caller_id:         str = ""
    dialed_number:     str = ""
    start_time:        datetime
    answer_time:       datetime | None = None
    end_time:          datetime
    forwarded_to:      list[str] = []
    agent_actions:     list[_WireEvent] = []
    prior_extension:   str | None = None
    final_destination: str | None = None

class _WirePage(BaseModel):
    data:        list[_WireCall]
    next_cursor: str | None = None
```

**Wire→domain mapping** in private `_map_wire_call`. Status normalization: `"answered"` → answered, `"voicemail"` → voicemail, anything else → `"unanswered"`. Direction normalization: `"outbound"`/`"internal"` → as-is, anything else → `"inbound"`.

**Preserve the TypeScript TODO markers verbatim** — these flag wire field names that need verification against a live response:

```python

#   Known confirmed: avoxi_call_id, agent_actions, { data: [...] } envelope.
#   Educated guesses: caller_id, dialed_number, start_time, end_time,
#   forwarded_to, next_cursor — align before merging to production.
```

**HTTP client lifecycle (decision from audit M4):**

`AvoxiClient` is a context manager. `__init__` constructs `httpx.Client` with timeouts and bearer header. `__exit__` closes it. Caller uses `with AvoxiClient(cfg) as client:`.

```python
self._client = httpx.Client(
    headers={"Authorization": f"Bearer {cfg.token}"},
    timeout=httpx.Timeout(connect=5.0, read=30.0),
)
```

**Retry policy (decision from audit M1):**

- Up to 3 attempts.
- On 401/403: raise immediately (custom `AvoxiAuthError`).
- On 429: read `Retry-After` header (integer seconds). Sleep `min(retry_after, 30)`. If header missing, fall back to exponential backoff: `0.5 * 2 ** (attempt - 1)`.
- On 5xx: exponential backoff (same formula).
- On other 4xx: raise (custom `AvoxiError`).
- Cap **total** retry sleep at 60 seconds — if exceeded, raise the last error.
- Network errors (`httpx.RequestError`) follow the 5xx backoff rule.

**Pagination:**

```
GET {base_url}/cdrs?start_time={iso}&end_time={iso}&limit=10000[&cursor={token}]
```

Loop while `_WirePage.next_cursor` is set. Empty window → return `[]`.

**Custom exceptions** (define at module top):

```python
class AvoxiError(Exception): ...
class AvoxiAuthError(AvoxiError): ...
```

### 7.5 `src/avoxi_audit/audit.py`

**Surface:** `audit_window(since: datetime, until: datetime, config: AppConfig) -> str`

**Behavior:**

1. Use `with AvoxiClient(config.avoxi) as client:` for resource lifecycle.
2. `calls = client.list_calls(since, until)`.
3. Compute `analyzed = [(c, classify(c, config.schedule)) for c in calls]`.
4. Build a compact JSON-serializable dict (`summary` — see schema below).
5. Send to LLM via `OpenAI(api_key=config.llm.api_key, base_url=config.llm.base_url)`.
   - `base_url=None` lets the SDK use its default (correct for `openai` provider).
6. Return the LLM's text response (markdown).

**Zero-call short-circuit (decision from audit M5):**

The stub for empty windows must use the **same section structure** as the LLM-generated report so downstream consumers see a stable shape:

```markdown
# On-call audit — {company_name}
**Window:** {since_iso} → {until_iso}

## Overview
No calls were recorded in this window.

## Missed calls during on-call hours
None.

## Other notable events
None.

## Recommendations
No action required.
```

Return this string directly (no LLM call, no API cost).

**JSON summary schema** (input to LLM):

```json
{
  "window":  {"since": "<iso>", "until": "<iso>"},
  "company": "<company_name>",
  "totals":  {"all": <int>, "missed": <int>, "byReason": {"<reason>": <int>}},
  "missedCalls": [
    {
      "id":        "<call_id>",
      "startedAt": "<iso>",
      "from":      "<phone>",
      "to":        "<phone>",
      "reason":    "<MissReason>",
      "steps": [
        {"at": "<iso>", "kind": "<StepKind>", "actor": "<str|null>"}
      ]
    }
  ]
}
```

Use `json.dumps(summary, indent=2, default=str)` — `default=str` handles `datetime` → ISO string.

**Prompt structure:**

System message:

```
You are an on-call audit assistant. You receive a structured JSON summary of telephone calls from an Avoxi system during an on-call window. Write a concise markdown report for the operations team. Focus on actionable missed calls during on-call hours. Be factual and brief.
```

User message (single string concatenation):

```
Write a markdown report with these sections:
## Overview
## Missed calls during on-call hours
## Other notable events
## Recommendations

<JSON summary here>
```

Use `client.chat.completions.create(model=config.llm.model, messages=[...])` and return `response.choices[0].message.content or "(no response from LLM)"`.

### 7.6 `src/avoxi_audit/cli.py`

**Surface:** `main() -> None` (entry point registered via `[project.scripts]`).

**Behavior:**

1. `argparse.ArgumentParser` with `--since` and `--until` (both optional).
2. Parse argv. Reject if exactly one of `--since`/`--until` is given (both or neither).
3. For each provided value:
   - Parse with `datetime.fromisoformat(value)`.
   - **Reject naive datetimes** (decision from audit M3): if `parsed.tzinfo is None`, print error to stderr and exit 1:
     ```
     --since and --until must include a timezone offset (e.g. 2026-04-29T21:00:00-03:00)
     ```
4. If neither provided, compute default window:
   ```python
   now = datetime.now(timezone.utc)
   since, until = previous_shift(now, config.schedule)
   ```
5. Call `narrative = audit_window(since, until, config)`.
6. `sys.stdout.write(narrative + "\n")`.
7. Wrap the whole thing in try/except — print error message to stderr and `sys.exit(1)` on any exception.

**Error message format:** keep it one line, no traceback. The traceback is for developers; CLI users see `error: <message>`.
